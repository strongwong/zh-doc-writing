# 文档结构与文件名

写单篇文档用不到本文件。规划一整套手册、文档站或 docs/ 目录时读它。

## 手册结构

一套完整的软件手册建议按下面组织。[必备] 的缺了要补，[可选] 按需要加。

- **简介**（Introduction）：[必备] 产品和文档的总体说明。读完知道这是什么、给谁用。
- **快速上手**（Getting Started）：[可选] 最短路径跑通一次。
- **入门篇**（Basics）：[必备] 目录，初级使用教程。
  - **环境准备**（Prerequisites）：[必备] 前置条件，写清版本号。
  - **安装**（Installation）：[可选]
  - **配置**（Configuration）：[必备]
- **进阶篇**（Advanced）：[可选] 目录，中高级开发教程。
- **API**（Reference）：[可选] 逐个接口说明。
- **FAQ**：[可选] 常见问题，只收真实被问过的问题。
- **附录**（Appendix）：[可选] 目录。
  - **术语表**（Glossary）
  - **最佳实践**（Recipes）
  - **故障处理**（Troubleshooting）：按“现象 → 原因 → 处理”写，现象里贴报错原文。
  - **版本说明**（ChangeLog）
  - **反馈方式**（Feedback）

范例：[Redux 文档](https://redux.js.org/introduction/getting-started)。

## 文件名

- 只用半角字符，不用中文，不含空格。
  - 差：`名词解释.md` → 好：`glossary.md`
- 用小写字母。约定俗成的说明文件除外：`README`、`LICENSE`、`CHANGELOG`。
  - 差：`TroubleShooting.md` → 好：`troubleshooting.md`
- 多个单词用连字符 `-` 连接，不用下划线。
  - 差：`advanced_usage.md` → 好：`advanced-usage.md`
- 仓库已有自己的命名习惯时，跟仓库走。

## 常见文档的骨架

**README**：一句话说明是什么 → 怎么装 → 最小可运行示例 → 配置项 → 链接到详细文档。不写项目愿景和“特性亮点”列表。

**设计文档**：背景（要解决什么问题，现状数据）→ 目标与非目标 → 方案 → 备选方案和不选的理由 → 风险与验证方法 → 待定问题。

**接口说明**：用途一句话 → 原型 → 参数表（名称、类型、取值范围、默认值）→ 返回值和错误码 → 调用示例 → 注意事项（线程安全、重入、时序约束）。

**问题报告 / 评审意见**：结论先行，再给触发条件、影响、位置、证据、建议。每条都能单独读懂。
